## 3. Tool notes

- **FS search service from the page:** `fetch('https://www.familysearch.org/service/search/hr/v2/personas?' + URLSearchParams({...}), {headers:{accept:'application/json'}, credentials:'include'})` returns JSON (`results`, `entries[].content.gedcomx`), 100 per page with `offset`. Params as in the UI (`q.surname`, `q.givenName`, `q.deathLikePlace`, `q.deathLikeDate.from/to`, `f.collectionId`, `.exact` = `on`). The total ignores the date limits, but results are ranked, so page until a page has no matching year. Each page takes ~10 s; run long loops in the background (`(async()=>{…})()` writing to a `window` variable) and poll, or CDP times out at 45 s.
- **Long JS output gets truncated around 1,000 characters.** Write it into the page (`document.body.innerHTML='<main><pre id=out></pre></main>'`, set `textContent`) and read it with `get_page_text`, which returns all of it.
- Collection IDs: **WHS pre-1907 death index = 1940759**; WI Marriages 1836–1930 index entries have no image; VA pension payment cards = M850.
- FS standardizes some 1820 places wrongly ("Madison, Montgomery" → Marne, Licking Co.). Always check "Event Place (Original)".
- 1820 image viewer: the record panel covers the image; close it (X, ~1078,57), scroll-zoom on the row, then `zoom` the row and the header.
- WHS website records search: gone (new site 404, legacy 500).
